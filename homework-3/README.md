# Реализация паттернов проектирования на Java

Этот репозиторий содержит реализации классических паттернов проектирования (GoF) на языке Java. Каждая реализация адаптирована под конкретную предметную область и доработана с учетом различных практик разработки (SOLID, потокобезопасность, иммутабельность).

## Содержание
1. [Стратегия (Strategy)](#1-стратегия-strategy) — Автомобили и заправка
2. [Цепочка обязанностей (Chain of Responsibility)](#2-цепочка-обязанностей-chain-of-responsibility) — Маршрутизация сообщений
3. [Строитель (Builder)](#3-строитель-builder) — Конфигурация сотрудника
4. [Заместитель (Proxy)](#4-заместитель-proxy) — Кэширование расписания поездов
5. [Декоратор (Decorator)](#5-декоратор-decorator) — Конфигуратор VPS-сервера
6. [Адаптер (Adapter)](#6-адаптер-adapter) — USB-кардридер для SD-карты

---

### 1. Стратегия (Strategy)
**Тема:** Автомобили и алгоритмы заправки.
- **Реализация:** Интерфейс `FillStrategy` и его конкретные реализации. Класс `Auto` использует композицию для делегирования поведения.
- **Замечание:** Внедрен **Null Object Pattern** (`NoFillStrategy`) для игрушечных машинок, что полностью избавило базовый класс от проверок на `null` и нарушенного полиморфизма.

### 2. Цепочка обязанностей (Chain of Responsibility)
**Тема:** Обработка сообщений разного уровня критичности (Log, Email, SMS).
- **Реализация:** Абстрактный обработчик с методом `handleMessage`, который решает, может ли он обработать запрос, или передает его дальше по цепи.
- **Замечания:**
    - Реализован **Fluent API** для удобного и читаемого построения цепи (`setNextSender().setNextSender()`).
    - Корректная остановка цепи после успешной обработки (или каскадная, в зависимости от требований).

### 3. Строитель (Builder)
**Тема:** Создание объекта `Employee` (Сотрудник) с обязательными и необязательными полями.
- **Реализация:** Вложенный статический класс `EmployeeBuilder`, следуя рекомендациям из "Effective Java" (Джошуа Блох).
- **Замечания:**
    - Добавлена **валидация данных** внутри метода `build()` (защита от создания невалидных объектов).
    - Гарантированная иммутабельность результирующего объекта (`final` поля).

### 4. Заместитель (Proxy)
**Тема:** Кэширующий прокси для получения расписания электропоездов (`TimetableTrains`).
- **Реализация:** `TimetableElectricTrainsProxy` перехватывает запросы, проверяет актуальность кэша и делегирует чтение с диска реальному объекту только при необходимости.
- **Замечания:**
    - Добавлена **потокобезопасность** (`synchronized`) для методов работы с кэшем.
    - Устранено дублирование кода поиска поезда с помощью `default`-метода в интерфейсе.

### 5. Декоратор (Decorator)
**Тема:** Динамическое расширение функциональности и стоимости VPS-сервера (RAM, SSD, DDoS-защита).
- **Реализация:** Базовый абстрактный декоратор `ServerDecorator` и конкретные декораторы, добавляющие свою стоимость и описание.
- **Замечание:**
    - Поля декораторов сделаны `final` для гарантии неизменяемости цепочки после создания.

### 6. Адаптер (Adapter)
**Тема:** Подключение SD-карты (`SdCard`) к компьютеру через USB-интерфейс (`UsbDevice`) с помощью кардридера.
- **Реализация:** Адаптер объектов (через композицию), реализующий целевой интерфейс и содержащий ссылку на адаптируемый класс.
